# Command audit

Latest audit: 2026-10-26. Previous audit: 2026-07-25.

## How usage was measured

`tsp` has no telemetry. This audit counts `tsp <command>` lines in Matt's
`~/.zsh_history`. It also checks the tmux bindings, the agent registry
(`~/.tsp/agent-runs.json`), and `~/.tsp/config.yaml`.

- The window is the three months after the previous audit, 2026-07-25 to
  2026-10-26.
- `tsp dash` is undercounted. Matt mostly opens it with `prefix d`, which runs
  `tsp dash` in a tmux popup and leaves no shell history.
- Arnold, the software factory, used to call `tsp spawn`. It now creates its
  own worktrees, so it is not a hidden caller.

## Used

| Feature | Uses, Jul–Oct 2026 | Last used | Notes |
|---|---|---|---|
| `tsp dir` | 67 | October | The main way into a project. |
| `tsp dash` | 16 typed, plus every `prefix d` | October | Open, New, attach, stop, clean, filter, and fold all stay. |
| `tsp project` | 10 | October | Only project creator. |

`completion` and `help` are generated by Cobra and remain available.

## Removed on 2026-10-26

| Feature | Last used | Why it went |
|---|---|---|
| `tsp list` (`txl`) | February | `tsp dash` lists every session and `Enter` jumps to it. |
| `tsp rm` | March | Dashboard `x` removes a session, or a session plus its worktree and branch. |
| `tsp cleanup` | February | Dashboard `x` covers worktree removal. Its sweep of half-deleted `.tsp-trash-*` directories now runs when `tsp dash` opens. |
| `tsp wtx-new` | February | `tsp spawn` and dashboard New create worktree sessions. It also hard-coded `~/work/code` instead of `spawn.worktree_base`. |
| `tsp wtx-here` | never | `tsp dir` opens a session for any configured directory. |
| `tsp wtx-rm` | February | Dashboard `x`. |
| `tsp middle` | February | A generic popup runner. `tmux display-popup` does the same job directly, as the `prefix d` binding shows. |
| `tsp version` | never | `tsp -v` prints the same version. |
| Dashboard delegation (`d`) | never | No delegated run ever reached the registry, `~/.tsp/delegate-output/` was never created, and the config never set `manager`. This removed child panes, the delegation prompt, stored delegate output, natural-language stop and cleanup routing, and the `manager` config section. Old `manager` keys still load and are ignored. Old delegated records are dropped when the registry loads. |

Unreachable helpers left from earlier removals also went: the second directory
walker in `internal/pathutil`, `ExpandEnvVar`, `DetectSessionGitInfo`,
`CreateSession`, `GetPaneCwdByIndex`, and `oldConfigPath`.

## Removed on 2026-07-25

| Command or feature | Reason |
|---|---|
| `tsp serve` and daemon subcommands | Existed solely for remote/mobile control; also owned the polling monitor and CI lifecycle watcher. |
| `tsp device` and pairing/notify subcommands | Mobile authentication, QR pairing, token storage, and push delivery are obsolete. |
| `tsp peek` | A second polling session dashboard. |
| `tsp txrm` | Strict subset of `tsp rm --sessions-only`. |
| `tsp new` | Wrapper duplicated `project`/`sandbox` while its advertised positional name was not used. |
| `tsp sandbox` | Duplicate project creator backed by an otherwise unused config section. |
| `tsp duck` | Novelty daemon/socket/popup unrelated to the focused project and agent workflow. |
| Dashboard PR/CI polling and fixed review actions | Mixed agent control with GitHub lifecycle automation and required polling/state inference. |

That round also removed the embedded web app, HTTP/WebSocket server, token
auth, device store, pairing flow, push client, launchd management, CI watcher,
event bus, notification/question pipeline, output-status inference,
`gorilla/websocket`, and `go-qrcode`.

## Before adding a command back

Check this table first. A new command should do something `tsp dash`, `tsp dir`,
or `tsp spawn` cannot, and should not need polling or a server.
